PPC Oversight System

Three tempos, one account. The daily tier protects, the weekly tier steers, the monthly tier decides. Each tier reads only the signals that have matured by the time it runs — which is the whole point of separating them, and the reason most PPC accounts oscillate instead of compound.

§1

Operating principles

Seven rules. If a cadence, a threshold or a report ever conflicts with one of these, the principle wins and the artefact gets rewritten. An oversight system without enforced principles is just a meeting schedule.

P1

Match the window to the data's maturity

Sponsored Products attribution runs 7 days (14 on some reports). The last 72 hours of conversion data is always incomplete. A keyword judged on three-day data is judged on a number that has not finished arriving.

P2

Sufficiency before action

No bid cut under 10 clicks. No negation under 2× target CPA in spend. No CVR read under 20 clicks. Below the bar the correct decision is keep observing — and that gets logged as a decision, not as silence.

P3

One lever per entity per cycle

Move the bid, or the placement modifier, or the budget. If all three move together and performance shifts, you have learned nothing about which one did it, and next cycle you are guessing again.

P4

Observation lock after every change

Any entity changed this cycle is frozen for 14 days; new campaigns for 21. Re-judging a change before it matures is the single most common cause of bids that oscillate for months without converging.

P5

Every action is graded

Each cycle opens by scoring the changes from two cycles ago — worked / flat / backfired — against the expected outcome written when they were made. A lever that reads flat twice on the same entity is retired for it, not repeated harder.

P6

Thresholds are set before the breach

Every trigger in §6 lives in a version-controlled config file. Thresholds are changed in the monthly review with a reason recorded — never argued in the moment, when the number in front of you is doing the arguing.

P7

A null result is an output

"No exceptions" is logged daily. An empty log and a skipped check look identical in hindsight, so the system requires the null row — it is the evidence the check ran.

§3

Daily tier — control

Fifteen minutes, seven checks, exception-based. The daily pass exists to catch breakage and stop loss, nothing else. If it starts producing bid changes it has stopped being oversight and become an optimisation pass running on immature data — the most expensive habit in Amazon PPC.

OwnerPPC Specialist
Timebox15 min
WhenEvery business day, before 10:00 local
Data as ofYesterday 23:59 marketplace time
OutputDaily Exception Log (or a NIL row)
D1
Account & ad eligibility

Suppressed or ineligible ads, policy flags, failed payment method, campaigns that hit an end date overnight. A campaign can be "active" in your plan and serving nothing.

Trigger any ineligible ad on a top-20 spend ASIN, or any unplanned campaign end
D2
Delivery integrity

Campaigns that had traffic in the prior 7 days and have now gone silent. Usually a paused ad group, a bid below the floor, a lost Buy Box, or a listing change — never nothing.

Trigger 0 impressions for 2 consecutive days after ≥ 500 impressions in the prior 7d
D3
Buy Box & inventory on advertised ASINs

The quiet killer: ads keep spending at full rate while conversion collapses. Losing the Buy Box does not stop delivery, it only stops sales. Stock cover is checked in the same pass.

Trigger Buy Box < 90% · or DOH < 21 days · or any OOS advertised child ASIN
D4
Spend pacing against the envelope

Month-to-date spend against the monthly envelope agreed in §5. Pace drift is corrected weekly, not daily — the daily job is only to see it early enough that the weekly pass can act.

Trigger MTD pace > ±10% of plan · escalates to P2 beyond ±20%
D5
Spend anomaly by campaign

A campaign whose daily spend departs sharply from its own recent behaviour. Up usually means a competitor left or a bid rule fired; down usually means delivery is broken.

Trigger daily spend > 150% or < 50% of its trailing 7-day mean
D6
Budget cap timing

Not whether a campaign capped, but when. A ranking campaign that goes dark at 16:00 is missing the highest-intent hours of the day, which is a ranking problem, not a budget problem.

Trigger out of budget before 18:00 · before 20:00 on a Ranking-objective campaign
D7
Runaway spend

The one conversion-adjacent check the daily tier is allowed, because at this magnitude the sample is no longer ambiguous. It is a circuit breaker, not an optimisation.

Trigger ≥ 3× target CPA spent · 0 orders · over ≥ 5 rolling days
Pre-authorised actions
  • Pause ads on an OOS or Buy-Box-lost ASIN, and log the reinstatement date.
  • Budget relief on a capped campaign — max +25%, once per campaign per week, within the monthly envelope.
  • Circuit-break pause on any campaign breaching D7.
  • Escalate anything else, with the log row as the ticket.
Explicitly out of scope
  • Bid changes of any size.
  • Placement modifier changes.
  • Adding negatives or harvesting search terms.
  • Creating, archiving or restructuring campaigns.
  • All of these wait for the weekly pass, where the data supporting them has settled.
§4

Weekly tier — steering

The tier that does the actual work. Nine steps, run in order, on a fixed weekday — Tuesday is the usual choice, so the weekend has settled and there is still a working week left to react in. The order is not cosmetic: gates precede bids because a bid set before its inventory and margin gate is known is a bid set blind.

OwnerPPC Manager decides · Specialist prepares
Timebox75–90 min
WhenFixed weekday, same slot every week
Windows14d bids · 30d budget & placement · 60d search terms
OutputDecided bulk + Weekly Change Log + 1-page summary
W1
Execution verification — did last week's changes land?

Diff last cycle's approved change log against the current bulk export, row by row. This is first for a reason: approved is not uploaded. Partial uploads, rejected rows and overwritten bids are the most common silent failure in a managed account, and every downstream conclusion is wrong if the changes never took.

Gate 100% of approved rows verified present, or the cycle does not proceed to W5
W2
Grade the matured cycle

Score every change made two cycles ago — now past its observation lock — as worked, flat or backfired against the expected outcome recorded at the time. This is what converts a change log into a control system rather than a diary.

Rule a lever flat twice on the same entity is retired for that entity and the next lever in the hierarchy is used
W3
Set the gates before touching anything

For each SKU: inventory cover (DOH), true break-even ACoS from that SKU's own margin, and the campaign's declared objective — Ranking, Discovery, Profitable Conversion or Defensive. Every later decision is judged against these three, and they differ per SKU.

Gate no bid, budget or placement decision is made for a SKU whose DOH, break-even and objective are not all known
W4
Search-term pass — negate, harvest, de-duplicate

Negate proven wasters, promote proven converters into exact, and check that the same term is not being bought three times across match types in the same portfolio. Self-competition inflates CPC against yourself.

Negate ≥ 2× target CPA spent, 0 orders, ≥ 10 clicks, 60d  ·  Harvest ≥ 2 orders at ≤ target ACoS, 60d
W5
Bid pass — by objective, step-capped

Bids move against the objective set in W3, not against a single account ACoS target. A Ranking keyword is allowed to run above break-even by design; a Profitable Conversion keyword is not. Step sizes are capped so a wrong call is cheap and reversible.

Step ±10–15% routine · ±25% correction · never two direction changes on one entity inside 14d
W6
Placement pass

Top-of-search, product-page and rest-of-search modifiers, read on 30-day data. Placement is the strongest single lever on ranking campaigns and the easiest to over-tune, so it moves slowly and one campaign at a time.

Step ≤ 20 percentage points · one move per campaign per 14 days
W7
Budget pass — reallocate inside the envelope

Money moves between campaigns, not into the account. The weekly tier is not permitted to grow total spend; it is permitted to spend the agreed envelope better. Envelope changes escalate to the monthly tier.

Constraint sum of weekly budgets ≤ monthly envelope ÷ days remaining
W8
Hygiene sweep

Enabled keywords inside paused ad groups, campaigns with no negatives, ad groups with no product ad, unassigned portfolios, targets whose SKU no longer exists. Individually trivial, collectively a steady leak.

Target zero open hygiene items carried more than two cycles
W9
Package, log, approve

Produce the decided bulk, the change log with an expected outcome and review date on every row, and a five-line summary. Nothing is uploaded before the log row exists — the log is written first, so that W1 next week has something to verify against.

Rule every changed row carries a rationale of ≤ 25 words and a dated expected outcome
Lever hierarchy — try in this order
  • 1. Bid — cheapest to reverse, smallest blast radius.
  • 2. Placement modifier — when the bid is right but the position is not.
  • 3. Budget — when the campaign is efficient and capped.
  • 4. Negation / harvest — when the traffic itself is wrong.
  • 5. Structure — last resort; escalates to monthly, resets learning.
Stop conditions for the cycle
  • W1 fails — changes never landed. Fix the upload, then restart.
  • A SKU's margin or inventory data is missing — that SKU is skipped, not guessed.
  • A proposed change exceeds the Manager's authority in §7 — it is proposed, not made.
  • Skipped items are logged as skipped, with the reason. Silence is not an outcome.
§5

Monthly tier — strategy

Half a day, within five working days of month close so that returns and fees have settled. The monthly tier asks a different question from the other two: not "is the account being run well?" but "is it being run toward the right thing?" It is the only tier permitted to change the envelope, the objective mix, the structure, or the thresholds the other tiers obey.

OwnerAccount Lead with PPC Manager
TimeboxHalf day
WhenWithin 5 working days of month close
WindowsClosed month · trailing 90d for structure
OutputReview Pack + next envelope + threshold changes
M1
Profit truth, not ACoS

Ad spend read against contribution margin per SKU, plus TACoS trend across the trailing six months. ACoS answers "was the ad efficient"; CM2 after ads answers "did the business make money" — and on a multi-SKU portfolio those two routinely disagree.

Reads TACoS 6-month trend · CM2 after ads per SKU · spend vs. contribution by objective
M2
Objective mix against product stage

Share of spend by objective compared with the target mix for each product's stage. A launch product carrying 70% Profitable Conversion spend is not being launched; a mature product carrying 40% Ranking spend is funding a race it has already won.

Reference mix Launch ≈ 50/30/15/5 · Scale ≈ 35/25/30/10 · Harvest ≈ 15/15/60/10  (Rank/Disc/Profit/Def)
M3
Rank progression against targets

Target keywords versus their rank targets, using the weekly rank log. The question that matters: is the ranking spend buying rank, or only buying sales at a worse ACoS than the profitable campaigns would have delivered? A ranking push with no rank movement over 8 weeks is a subsidy.

Sufficiency stop target rank held for 21 days → step ranking spend down 20% per cycle and watch
M4
Lever effectiveness & decay

Aggregate the month's W2 grades by lever. Levers decay: bid increases that bought volume in month one often read flat by month four, which means the constraint has moved somewhere else — usually to creative, price, or the listing.

Signal a lever < 40% "worked" across the month is escalated as a diagnosis problem, not a tuning problem
M5
Coverage & competitive position

Keyword gaps against the master list, share of voice on the head terms, new entrants, and price or Buy Box pressure. Much of what looks like PPC decay is a competitor changing price, and no bid change fixes that.

Reads uncovered terms ≥ 500 SV · SOV on top-20 terms · competitor price deltas · new advertisers on head terms
M6
Structure & campaign lifecycle

Every campaign is placed on the lifecycle — launch, scale, harvest, sunset — and anything that has stalled is acted on. This is the only tier allowed to create or archive campaigns, because structural change resets learning and must be rare.

Sunset < 10 clicks and 0 orders over 60 days → archive · Promote 3 consecutive cycles at ≤ target ACoS → scale
M7
Next month's envelope and forecast

Set the budget envelope by objective for the coming month against seasonality, inventory cover and the launch calendar. This number is what the weekly tier is then constrained by — it is set here, once, deliberately.

Constraint envelope capped by inventory: no objective may be funded past its SKU's sell-through cover
M8
Threshold review and stakeholder report

Any threshold in §6 that fired constantly or never fired is retuned, with the reason recorded. Then one report to the brand owner in Finding → Why it matters → Action → Expected impact, which is the only format non-specialists reliably act on.

Rule threshold changes are versioned in config with a date and a reason — never adjusted silently mid-month
Decisions reserved to this tier
  • Budget envelope — total and by objective.
  • Objective reassignment for a campaign or SKU.
  • Campaign creation, archiving, restructure.
  • Threshold changes to §6.
  • Authorising deliberately unprofitable ranking spend, with an end date attached.
Quarterly extension
  • Full account architecture and naming audit.
  • Match-type and duplication audit across the whole portfolio.
  • Break-even and margin refresh from current COGS and fees.
  • Review of this system: which checks earned their time, which did not.

§9

Failure modes

Six ways this system decays. Every one of them has been observed in accounts that had a documented cadence — the cadence is not the control; the enforcement is. Check for these at the quarterly review.

Daily optimisation creep

The daily pass starts nudging bids because the data is right there. Conversions have not settled, so the nudges are noise-chasing, and bids oscillate for months without converging.

GuardBid columns are absent from the daily view. If it is not on screen it does not get touched.

Approved ≠ uploaded

Decisions are made, the bulk half-fails on upload, nobody diffs it, and next cycle reads results from changes that were never live. The account looks unresponsive to good decisions.

GuardW1 runs first and blocks the cycle. The verified ✓ column is not optional.

The ungraded change log

Changes are recorded but never scored, so the log becomes a diary. Levers that stopped working keep being pulled because nothing ever said they stopped.

GuardW2 is a gate, not a courtesy. Expected outcome is a required field at write time.

One ACoS target for every SKU

A single account-wide target ignores that break-even differs per SKU and that a Ranking keyword is supposed to exceed it. Profitable products get starved to subsidise thin ones.

GuardW3 gates every decision on that SKU's own break-even and declared objective.

Severity inflation

Everything becomes P1 because P1 gets attention. Within a quarter the ladder carries no information and genuine emergencies queue behind routine drift.

GuardSeverity comes from the fired threshold, never from the reporter. Reviewed at M8.

Silent thresholds

A threshold set too loose never fires and looks like health; set too tight it fires constantly and gets ignored. Either way the check has stopped being a check.

GuardM8 reviews fire rates. Never-fired and always-fired are both defects.
